# 组内统一评价规则(缺陷识别的检出率、误报率、准确率)

## 一、为什么要制定这套规则

**1. 作业公式本身算不出来。**
作业给了三个公式:检出率 = 识别出的真正缺陷个数 ÷ 人工缺陷个数;误报率 = 识别出的非缺陷个数 ÷ 人工缺陷个数;准确率 = 正确分类的缺陷个数 ÷ 识别出的缺陷个数。
但没有规定:算法画出的一块区域,**怎样才算"找到了"某个人工缺陷,怎样才算"非缺陷"(误报)**。不补这条规则,三个公式没法计算。

**2. 判法不同,数字相差极大。**
同一个模型的同一批预测,换一种判法:按本规则检出约 83%;按旧的"IoU ≥ 0.3 一对一配对"只有约 59%;按"每张图每类有没有"的图像级算法超过 90%。三人各用各的判法,对比表里的数字就没有意义。

**3. 现有的几种判法都有明显缺陷**(用同一批构造预测检验,验证集 1884 张,结果为 检出 / 误报 / 准确,%):

| 预测 | 本规则 | "碰到就算对"规则 | IoU ≥ 0.3 一对一 |
|---|---|---|---|
| 把标注本身当预测(完美预测) | 100 / 0 / 100 | 98.4 / 0 / 100 | 100 / 0 / 100 |
| 相邻碎块合并 | 100 / 0 / 100 | 99.8 / 0 / 100 | **93.2** / 0 / 100 |
| 每个缺陷画成外接矩形 | 99.3 / 0.5 / 99.5 | 99.7 / 0 / 100 | **94.6** / 0.9 / 99.1 |
| 缺陷被切成碎段(缝宽 10 像素) | 96.4 / 0 / 100 | 90.7 / 0 / 100 | **27.8 / 1064 / 2.6** |
| 作弊:有缺陷的图把出现的类别整张报满 | 3.5 / 35 / 9 | **100 / 0 / 100** | 0.9 / 37 / 2.3 |
| 作弊:每张图四类都整张报满 | 3.5 / 252 / 0 | **100** / 120 / 14 | 0.9 / 267 / 0.3 |

- **IoU 一对一**会冤枉位置正确的预测:只要形状和手画标注不一样、或者把一条缺陷报成几段,就判成漏检甚至大量误报。
- **"只要碰到标注就不算误报"**会被钻空子:把整张图报成缺陷,能拿满分。
- **本规则**两头都顾到了:位置正确的预测得分在 96%~100%,整张乱报的检出只有 3.5%。

**4. 设计原则。**
- 贴合作业原文:"检出"就是缺陷被找到了;"误报"就是报在了**非缺陷**(干净钢板)上。
- 不冤枉位置正确的预测,也不放过报在干净钢板上的预测。
- 每个参数都说明理由,关键参数用数据核对过。

## 二、规则

**输入**:每张图的人工标注和算法预测各一组 4 类二值掩码(原图 1600×256)。预测用各自算法**最终输出**的结果(各自的阈值、后处理照常,不为评价重新调参;评价时不再额外删除小块)。

**怎么数**
1. 人工缺陷:每一类分开,取 8 连通区域,一块算一个。不膨胀、不合并、不删小块。
2. 预测块:每一类分开,取 8 连通区域,一块算一个。

**判定(按顺序)**
1. **误报**:把所有人工缺陷(不分类别)向外扩 15 像素,得到"缺陷附近区域"。一个预测块落在这个区域里的面积 **< 它自身面积的 50%**,算 1 个误报。误报块不参与后面的检出判定。
2. **检出**:其余预测块不分类别合在一起;一个人工缺陷被盖住的面积 **≥ 它自身面积的 30%**,算检出。
3. **分类正确**:检出的缺陷上,盖住它的预测像素里数量最多的那一类,与人工类别相同,算分类正确。
4. **算法识别出的缺陷数** = 检出数 + 误报块数。

**公式**(整个数据集先累计个数,再算比例):

| 指标 | 公式 |
|---|---|
| 检出率 | 检出的人工缺陷数 ÷ 人工缺陷总数 |
| 误报率 | 误报块数 ÷ 人工缺陷总数 |
| 准确率 | 分类正确数 ÷(检出数 + 误报块数) |

## 三、每条规则为什么这样定

**1. 检出用"覆盖率",不用 IoU**
- 覆盖率 = 重叠面积 ÷ 人工缺陷面积;IoU = 重叠面积 ÷ 两者合起来的面积。
- 人工标注是手画的,边界粗、常圈进背景,还常把一条缺陷拆成几块画。IoU 要求形状、大小都接近并且一对一配对,会把位置正确的预测判错(见第一节的表:外接矩形只有 94.6%,碎段只有 27.8%)。
- 作业要求的是"数缺陷个数",关心的是"找没找到",覆盖率正好回答这个问题。预测画大了的问题交给误报规则管。

**2. 覆盖率取 30%**
- 标注圈进了背景,预测通常比标注"收得紧",要求盖住 100% 不现实;30% 表示预测确实落在了这个缺陷上,不是擦边。
- 换成 10% 或 50%,最终方案的检出率在约 78%~84% 之间变化,误报率和准确率基本不变,结论不受这个数影响。

**3. 误报看"预测块自身有多少落在缺陷附近",而不是"有没有碰到缺陷"**
- 作业说误报是识别出的"非缺陷"。一条缺陷被报成几段,每段都在缺陷上,不是非缺陷,不该算误报。
- 只看"有没有碰到"会被钻空子:一大块预测只要擦到缺陷一个像素就不算误报,把整张图报满能拿满分(见第一节)。
- 看预测块**自身**的比例就堵住了:整张图报满时,只有一小部分落在缺陷附近,判为误报;误报块不算检出,所以检出也是 0。

**4. 误报判定取 50%**
- 这是"多数原则":一块预测大半在缺陷附近,就算报对了地方;大半在干净钢板上,就算误报。50% 是最自然的分界线,不偏向哪一边。

**5. 外扩 15 像素**
15 像素最初按经验定(标注边界粗、碎块之间有空隙),之后用最终方案的预测做了核对:
- **预测正常会超出标注多少**:与标注相交的预测块,伸到标注外的部分离标注的距离,中位数约 8 像素,75% 在 19 像素以内。15 像素大致覆盖了"沿真实缺陷画、自然会超出手画标注"的距离。
- **不会把不相干的缺陷连在一起**:同一张图同类相邻缺陷的最近距离,中位数约 37~49 像素,只有约 21~28% 的缺陷在 15 像素内有同类邻居。
- **结果对这个数不敏感**:外扩从 0 加到 10 像素,误报率下降很快(留出集 17.9% → 11.7%);过了 10~15 像素基本走平(15 像素 11.1%,50 像素 9.9%)。与 15 相比,取 10 只有约 17~19 个预测块(共约 2100 个)改变判定。
- **被放过的块确实报在缺陷上**:随机抽查"外扩 0 像素算误报、15 像素不算"的预测块,都压在真实缺陷上,只是画得比标注宽,或把相邻几条缺陷连成一块。
- **与作业的定位精度相当**:按组内硬件设计每像素约 0.2075 mm,15 像素约 3.1 mm,与作业横向位置偏差要求 3.3 mm(板宽 3300 mm 的 0.1%)相当。

**6. 评价时不额外删除小预测块**
- 各人的后处理本来就会删掉噪点小块,评价时再删一次,等于改了别人的算法。
- 标注里本身就有很小的缺陷(验证集约 1.6% 的缺陷小于 100 像素)。评价时删小块,连完美预测都拿不到 100%(第一节"碰到就算对"规则的完美预测只有 98.4%,就是这个原因)。
- 留下的噪点如果报在干净钢板上,会按误报规则计入误报,不会被放过。

**7. 用 8 连通**
- 斜对角相挨的像素看起来是连在一起的,8 连通是图像处理划分区域的通用做法;标注和预测用同一种方式数,才公平。

**8. 准确率按"缺陷"算,分母是检出数 + 误报数**
- 作业原文是"正确分类的缺陷个数 ÷ 识别出的缺陷个数",单位是缺陷。
- 如果按"预测块"算,一个缺陷被报成 3 段就要算 3 次,报得越碎分母越大,和作业的意思不符。

**9. 分类正确取"盖住的像素最多的类别"**
- 一个缺陷上可能同时有几类预测,取占多数的那一类作为算法给出的类别,符合"以主要判断为准"的直觉。

## 四、典型情况

| 情况 | 结果 |
|---|---|
| 预测与标注完全一致 | 检出 1,误报 0,分类正确 |
| 有缺陷但没报 | 漏检 1 |
| 无缺陷的图上报了一块 | 误报 1 |
| 位置对、类别错 | 检出 1,分类不正确 |
| 只盖住缺陷的 19%(块在缺陷附近) | 不算检出,也不算误报 |
| 两个相邻缺陷被预测连成一块 | 检出 2,误报 0 |
| 一个缺陷被报成 3 段 | 检出 1,误报 0 |
| 缺陷报对了,远处又多报一块 | 检出 1,误报 1 |
| 整张图报满 | 通常判为误报,检出 0 |

## 五、这套规则的局限(如实说明)
- 外扩距离对误报率有约 1 个百分点的影响(留出集取 10 像素时 11.7%,取 15 像素时 11.1%)。
- 预测可以比缺陷"画大一圈"而不被扣分,只要大半落在缺陷附近;这是为了适应粗糙的手画标注而有意保留的宽松度。
- 缺陷本身占了大半张图时,整图报满的预测也能过 50% 的门槛(构造实验中只占约 3.5%)。

## 七、参考代码
附带两个文件(放在同一个文件夹里即可,只需要 numpy 和 opencv-python):
- `evaluate_v2.py`:评价函数本体。
- `评价示例.py`:演示用法,包括从 Kaggle 格式的 RLE 解码成掩码、几个小例子的自检、对整个数据集计算三项指标。

用法:对每张图准备 `gt4`、`pred4` 两个形状为 (4, 256, 1600) 的 0/1 数组,调用
`evaluate_v2([(gt4, pred4), ...], covs=(0.3,), min_area=0)[0.3]`,结果里的 `detect_rate`、`false_rate`、`accuracy` 就是三项指标。
`min_area=0` 表示评价时不额外删除小块(已设为默认值)。运行 `python 评价示例.py` 可以先自检。
